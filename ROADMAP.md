# Roadmap

Built so far: 165 species across 18 orders, 2 habitats, triggerable behaviors with slow motion and close-up, an auto mode where the bird chooses for itself, a species list sorted by how likely each bird is this month, the class hierarchy explorer, and an interface on `@kyzarky/ui`.

### 1. Favicon
An SVG in `public/` and a `<link>` in `index.html`.

### 2. Browser tests
One Playwright run on a phone-sized screen with an axe accessibility check, as in Fluent Prior, added to `npm run verify` so CI runs it.
- Load the page, switch scene and bird, trigger every enabled behavior, toggle Auto and Close-up.
- Fail on any console error.
- Check that behaviors the scene cannot support are disabled and inert.

No screenshot comparison: the canvas animates, so it would be flaky. Add it if a rendering regression gets through.

### 3. Fold species feeding behaviors into `forage`
69 species override `forage()` only to call their own feeding behavior (`return this.berryPass()`), so the same action is listed twice. Instead, `forage` stays the one feeding behavior and a species relabels it in its own table. `behaviorsOf` already lets a lower class replace a spec:

```ts
static behaviors = { forage: { label: 'Berry pass', cue: '…' } };
```

- The named method (`berryPass`) becomes a protected helper and leaves the table.
- Auto mode's `forage` weight of 4 then covers species feeding too.
- A species with two genuinely different feeding methods, such as a kestrel that both hovers and hunts from a perch, keeps the second one as its own behavior.
- A test fails if a behavior in a table only returns another behavior.

### 4. Behavior weights for auto mode
Rule: in auto mode, everything a bird can do comes up at least once every 2–3 minutes. A bird runs about 6–8 behaviors a minute (a 1.5–4 s pause plus the behavior itself), so no behavior's weight can fall below about 1/20 of the total.
- A vitest runs `choose()` for every species in every scene it visits and enforces that floor.
- Within it, raise feeding and calls and lower displays.

### 5. Rarity in field notes
How many of a bird there are, as opposed to how likely it is to be seen here this month. A new optional field on `Ecology`:

```ts
rarity?: { status: 'LC' | 'NT' | 'VU' | 'EN' | 'CR'; population?: string; source: string };
```

Shown as one more line in field notes; nothing else reads it. Most of the work is research: IUCN status plus a regional population estimate (Partners in Flight, eBird abundance) for each species, done in batches by taxonomy file.

### 6. Food in the scene
A habitat declares its food, which exists whether or not a bird is feeding: an insect swarm, fish schools under the water, an anthill, berries on some shrubs, seed on the grass.
- `World` steps it: food drifts, is eaten, and comes back.
- Feeding behaviors go to real food (`findFood('berry')`) instead of picking a perch.
- Food takes over part of `needs`: a scene without berries disables berry feeding through `missing()`.

Done after step 3, so each merged feeding behavior is only rewritten once.

### 7. Sexes and juveniles
A new optional static on species, `variants: { female?: Partial<Look>; juvenile?: Partial<Look> }`, merged over the resolved `Look`, and a picker by the stage. Flocks use it to mix plumages.

### 8. Flock toggle
A switch beside Auto and Close-up that fills the stage with a flock of the selected species, so you can see how it looks and acts in a group: a quail covey with a sentinel, bushtits streaming bush to bush, a tight starling flock wheeling, a goose V, scoters rafting offshore.
- `Stage` steps and draws a list of birds. Zoomed out, the camera follows the flock's center.
- A per-class `flock: { size, spacing }` static merged down the lineage. Solitary species show a loose pair at most.
- First version: each bird runs auto mode on its own, keeping its spacing and sharing a heading when the flock moves. That already gives a covey or a raft.
- Then flock-level behaviors for coordinated shapes: starling wheeling, the goose V, a covey sentinel.
- Mixed flocks, such as chickadees with nuthatches or gulls mobbing an eagle, come after.

### 9. Location-aware birds and scenes, generated by an agent
When someone opens the page, ask for their location and load the best birds and scenes already available for it. Then ask an agent to create new scenes and birds as needed, with notes and behaviors specific to that location. The new content is stored in that visitor's browser, and a provisional copy goes to a queue for approval or edits.

The site is static on GitHub Pages and species are TypeScript classes, so each phase below ships separately:

1. **Regions as data.** `presence` becomes per region, with the Miller Peninsula as the first region. Scenes move to JSON; `HABITATS` is already plain data. Data species are JSON that names an existing genus or family class and overrides traits and behavior labels only.
2. **Location prompt.** Geolocation, rounded to a coarse grid; if it is denied, use the default region. Pick the nearest region, then its best scene and bird. No backend needed.
3. **Generation endpoint.** A small serverless function (for example a Cloudflare Worker) calls Claude and returns region notes, species and scenes as JSON. The JSON is validated against a schema on the server and again in the browser, then stored in IndexedDB. Generated code is never run: a species that would need a new behavior gets the closest existing behaviors, and the new method goes to the queue as a request.
4. **Approval queue.** The endpoint opens a GitHub PR with the JSON files. Merging approves it; edits happen in the PR.
5. **Guardrails.** Rate limit and cost cap on the endpoint. Only the coarse location leaves the browser. Results are cached by region, so the next visitor from the same area does not trigger a new generation.

Still to decide when this starts: where the endpoint is hosted, and whether an admin page should replace PRs.

## Deferred

### Side-by-side compare
Two stages in split view, each with its own bird, running the same behavior in sync. The cases that motivated it:
- Hummingbird hover next to kingfisher hover.
- Chicken `flush()` next to quail `flush()`.
- Galliform `scratch()` next to towhee `doubleScratch()`.
- Crow flight next to raven flight.

`Stage` already takes a bird as a prop, so this is mostly layout plus a shared clock.

### ID quiz
A silhouette performs behaviors and you name the species from movement alone. Needs a silhouette flag in `drawBird` (fill everything one color) and a small quiz component. Good fit with auto mode.

## Other ideas

- **Things the renderer cannot draw yet.** White outer tail feathers (junco), a wing epaulet (Red-winged Blackbird), a rump patch (Yellow-rumped Warbler), a head that turns without the neck (owls), and rodent prey for hawks and owls. Each is worked around in the species files today.
- **Sound.** Real recordings in place of the text mnemonics.
- **Tide and time of day** on the beach habitat, changing which behaviors are available.
- **Wind.** A wind vector in `World` that `flyTo` and `hoverFor` read, so gulls and kingfishers can kite into it.
- **A theme switch,** and a night scene to go with the dark theme.
