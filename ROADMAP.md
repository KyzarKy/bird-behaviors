# Roadmap

Built so far: 165 species across 18 orders, 2 habitats, triggerable behaviors with a close-up, an auto mode where the bird chooses for itself and everything comes up every few minutes, one `forage` behavior per bird, food in the scene for each bird with peeks and regrowth (see [docs/behaviors.md](docs/behaviors.md#food-in-the-scene)), a species list sorted by how likely each bird is this month, female and juvenile plumages for species that have them (`variants`, picked under the stage), the class hierarchy explorer, browser tests on a phone screen, and an interface on `@kyzarky/ui`.

### 1. Flock toggle
A switch beside Auto and Close-up that fills the stage with a flock of the selected species, so you can see how it looks and acts in a group: a quail covey with a sentinel, bushtits streaming bush to bush, a tight starling flock wheeling, a goose V, scoters rafting offshore.
- Mix plumages from the species' `variants` (Mallard hens with drakes, a juvenile among adult eagles).
- `Stage` steps and draws a list of birds. Zoomed out, the camera follows the flock's center.
- `ecology.flockSize` and `flockSpacing`, merged down the lineage like the rest of `ecology`. A species usually seen alone has a size of 1 and no Flock setting.
- First version (built, see [docs/behaviors.md](docs/behaviors.md#flocks)): each bird runs auto mode on its own in one shared world, and the flock moves off together now and then. That already gives a covey or a raft. Flock sizes are a first pass per family.
- Then flock-level behaviors for coordinated shapes: starling wheeling, the goose V, a covey sentinel.
- Mixed flocks, such as chickadees with nuthatches or gulls mobbing an eagle, come after.

### 2. Location-aware birds and scenes, generated by an agent
When someone opens the page, ask for their location and load the best birds and scenes already available for it. Then ask an agent to create new scenes and birds as needed, with notes and behaviors specific to that location. The new content is stored in that visitor's browser, and a provisional copy goes to a queue for approval or edits.

The site is static on GitHub Pages and species are TypeScript classes, so each phase below ships separately:

1. **Regions as data.** `presence` becomes per region, with the Miller Peninsula as the first region. Scenes move to JSON; `HABITATS` is already plain data. Data species are JSON that names an existing genus or family class and overrides traits and behavior labels only.
2. **Location prompt.** Geolocation, rounded to a coarse grid; if it is denied, use the default region. Pick the nearest region, then its best scene and bird. No backend needed.
3. **Generation endpoint.** A small serverless function (for example a Cloudflare Worker) calls Claude and returns region notes, species and scenes as JSON. The JSON is validated against a schema on the server and again in the browser, then stored in IndexedDB. Generated code is never run: a species that would need a new behavior gets the closest existing behaviors, and the new method goes to the queue as a request.
4. **Approval queue.** The endpoint opens a GitHub PR with the JSON files. Merging approves it; edits happen in the PR.
5. **Guardrails.** Rate limit and cost cap on the endpoint. Only the coarse location leaves the browser. Results are cached by region, so the next visitor from the same area does not trigger a new generation.

Still to decide when this starts: where the endpoint is hosted, and whether an admin page should replace PRs.

## Deferred

### How likely you are to see it, here and today
What field notes should eventually answer: the odds of actually seeing this bird where you are today. That depends on location, date, habitat, time of day and how detectable the bird is, which is mostly item 2's work. World population and Red List status alone did not answer it, so they were taken out of the app; the data for all 163 assessed species is kept in [`research/rarity/`](research/rarity/README.md) as one input.

### Side-by-side compare
Two stages in split view, each with its own bird, running the same behavior in sync. The cases that motivated it:
- Hummingbird hover next to kingfisher hover.
- Chicken `flush()` next to quail `flush()`.
- Galliform `scratch()` next to towhee `doubleScratch()`.
- Crow flight next to raven flight.

`Stage` already takes a bird as a prop, so this is mostly layout plus a shared clock.

### ID quiz
A silhouette performs behaviors and you name the species from movement alone. Needs a silhouette flag in `drawBird` (fill everything one color) and a small quiz component. Good fit with auto mode.

## Other ideas

- **Things the renderer cannot draw yet.** White outer tail feathers (junco), a wing epaulet (Red-winged Blackbird), a rump patch (Yellow-rumped Warbler), a head that turns without the neck (owls), and prey carried in hawk and owl talons (voles peek on the ground, but are not drawn in a bird's feet). Each is worked around in the species files today.
- **Prey that reacts.** Baitfish scatter from a diving bird, the small-bird flock flushes from a hawk, a vole bolts. Today food only peeks on its own timer.
- **Sound.** Real recordings in place of the text mnemonics.
- **Tide and time of day** on the beach habitat, changing which behaviors are available.
- **Wind.** A wind vector in `World` that `flyTo` and `hoverFor` read, so gulls and kingfishers can kite into it.
- **A theme switch,** and a night scene to go with the dark theme.
